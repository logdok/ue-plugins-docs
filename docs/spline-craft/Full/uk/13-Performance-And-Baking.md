# Продуктивність і запікання

*[🇬🇧 English](../en/13-Performance-And-Baking.md) | 🇺🇦 Українська*

## Скільки коштує структура

Секція **Stats** у панелі Details показує результат останньої збірки: скільки інстансних
компонентів, скільки всього інстансів, скільки Spline Mesh компонентів і скільки
процедурних мешів (полігонів). Дивіться туди, коли структура починає здаватися важкою.

## Line проти Curve

- **Line** — усі меші йдуть в `InstancedStaticMeshComponent`, по одному компоненту на
  унікальний меш. Дешево, вся структура лишається редагованою. Підходить для більшості
  сцен.
- **Curve** — кожен елемент кожного прольоту стає окремим `SplineMeshComponent`. Кількість
  компонентів росте швидко: друга секція на сплайні з 50 точок — це ще ~50 компонентів.
  Вмикайте Curve лише там, де меш справді має гнутися вздовж кривої, і слідкуйте за Stats.

## Великі статичні структури: збудуй і запечи

Для довгих огорож, парканів, доріг і трас — коли параметри вже фінальні —
**рекомендований шлях це [Merge to Static Mesh](11-Merge-To-Static-Mesh.md)**:

1. Повністю налаштуйте структуру.
2. Виконайте злиття — уся геометрія стає одним ассетом `StaticMesh`.
3. Увімкніть на ньому **Nanite**.

Після цього рушій обробляє структуру як звичайну статичну сітку з Nanite: пер-кластерне
відсікання й деталізація на будь-якій відстані, без ручних LOD і без витрат на інстансинг.
Це майже завжди кращий результат, ніж намагатися тримати живими тисячі Spline Mesh
компонентів.

Мінус — структура «замерзає»: щоб її змінити, повертаєте актор SplineCraft і мержите знову.

## Порада щодо кількості унікальних мешів

У режимі Line компоненти діляться за ключем «меш + матеріали». Що менше **різних** мешів і
матеріалів у структурі, то менше компонентів і draw calls. Випадкові меші з великого списку
множать кількість ISM-компонентів.

## Освітлення та запікання

- **Mobility = Static** — потрібно, щоб компоненти брали участь у запіканні статичного
  освітлення.
- Дочірні актори кроків **Build Scenario** примусово `Movable` — статичного запеченого світла
  на них не буде. Для «замороженого» результату — звичайний актор без сценарію або
  Merge to Static Mesh.
- Для фінального білду великих структур комбінація Merge to Static Mesh + запечене
  освітлення дає найпередбачуваніший результат.
