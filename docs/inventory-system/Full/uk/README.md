# Посібник користувача InventorySystem

*[🇬🇧 English](../en/README.md) | 🇺🇦 Українська*

Дата-керована система інвентаря та спорядження для **Unreal Engine 5.7** з
повноцінною підтримкою мультиплеєра.

Предмети створюються як Data Assets, геймплей-код викликає один метод, решту робить
плагін — включно з мережевою реплікацією.

> **Версія 1.0** · Runtime · UE 5.7 · [Примітки до випуску](Release-Notes.md)

---

## Швидкий старт

**1. Підключіть плагін.** Скопіюйте `Plugins/InventorySystem` у теку `Plugins/` свого
проєкту та ввімкніть його: **Edit → Plugins → Inventory System**.

**2. Створіть предмет.** Content Browser → правий клік →
**Miscellaneous → Data Asset → ISItemDefinition**. Назвіть `DA_HealthPotion`, задайте
`DisplayName`, і в полі **Fragments** додайте:

- **Stackable** → `MaxStackSize = 10`
- **Consumable** → `ConsumeAmount = 1`

**3. Дайте персонажу інвентар.** Blueprint персонажа → **Add Component → Inventory**.

**4. Перевірте.** Натисніть Play і відкрийте консоль:

```
InvGive Potion 5      видати собі 5 зілль
InvOverlay            відкрити інспектор
```

Готово — предмети видаються, стакуються й використовуються.

З коду те саме:

```cpp
int32 Remainder = 0;
InventoryComponent->TryAddItem(PotionDefinition, 5, Remainder);
```

Цей рядок працює **і в одиночній грі, і на клієнті мультиплеєра** — без жодної гілки
`HasAuthority()` з вашого боку.

## Три ідеї, на яких тримається плагін

Якщо читати лише один абзац — читайте цей.

**1. Предмет — це набір фрагментів, а не клас.**
Немає базового класу «зброя» чи «зілля». Меч — це `Equippable + Durability`, зілля —
`Stackable + Consumable`, смолоскип — усі три одразу: `Equippable + Durability +
Consumable` (тримається в руці, має запас пального й витрачається при використанні).
«Усі три» — це три з чотирьох щойно згаданих типів, а не всі фрагменти плагіна: їх
усього п'ять (`Stackable`, `Equippable`, `Consumable`, `Durability`, `Weight`). Додати
здатність = додати фрагмент; код інвентаря при цьому не змінюється.

**2. Один API для будь-якого режиму гри.**
Кожен метод, що змінює стан, називається `Try*` і викликається звідусіль. В одиночній
грі він виконується на місці й не створює RPC узагалі; на клієнті — сам пересилається
на сервер.

**3. Те, що робить копію унікальною, живе в екземплярі.**
Меч на 12/100 міцності й новий меч посилаються на той самий ассет, але мають різні
значення в екземплярі — і саме тому не об'єднуються в стек.

## Домовленості

- **«Тип предмета»** — ассет `UISItemDefinition`. **«Екземпляр»** — конкретна копія в
  чиємусь інвентарі (`UISItemInstance`).
- Сніпети коду — на C++, якщо не вказано інше. **Кожна показана функція викликається і
  з Blueprint** — плагін не має API, доступного лише з коду.
- «Інвентар» означає `UISInventoryComponent`, «спорядження» — `UISEquipmentComponent`.
